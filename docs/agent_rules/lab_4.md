Агент изучает эти решения и результаты проверки. Если сведений не хватает, запрашивает их у студентки, а не выбирает схему ансамбля сам. Только после выполнения этих условий можно писать параллельную инфраструктуру. Она сохраняет семантику проверенного последовательного алгоритма.

Условие требует последовательное и параллельное обучение элементов, а также параллельное получение их предсказаний. Достаточно верхнего уровня ансамбля. Конкретное распределение задач определяется решениями студентки; универсальные пул потоков, очередь и планировщик без необходимости не создаются.

Обязательные свойства параллельного кода:

- Для создания потоков используется только `std::jthread` из C++20.
- При `n_jobs == 1` выполняется последовательный путь; число рабочих потоков не превышает `n_jobs` и число элементов ансамбля.
- Общего изменяемого RNG нет; каждый элемент и его RNG изменяет один рабочий поток.
- Исходная матрица и отклики доступны рабочим задачам только для чтения.
- Контейнеры моделей, результатов и ошибок подготовлены до запуска потоков; совместного `push_back` нет.
- Каждая задача пишет результаты и ошибки в собственные ячейки. Вложенная модель не использует общий незащищённый изменяемый рабочий буфер.
- Все данные, захваченные по ссылке, живут до завершения потоков.
- Все потоки завершены до чтения результатов и агрегации; одного будущего уничтожения `jthread` для более раннего чтения недостаточно.
- Итоговая агрегация выполняется после завершения всех потоков, в порядке номеров моделей, независимо от порядка завершения задач.
- Исключения перехватываются внутри рабочих функций, сохраняются через `std::current_exception()` в заранее подготовленные ячейки `std::exception_ptr` и передаются вызывающему коду через `std::rethrow_exception()` после завершения всех потоков.
- При ошибке частично построенный ансамбль не считается успешно обученным.

`std::jthread` сам не передаёт исключения и не устраняет гонки. Итоговый код студентка должна понимать и уметь объяснить.

## Предметные требования как контекст для проверки

Этот раздел нужен для объяснений, диагностики и проверки; он не разрешает агенту реализовывать алгоритмы.

### CART и SplitFinder

Обычное дерево и деревья леса используют один CART и один поиск порога. Сохраняются существующие узлы с `std::unique_ptr`, композиция моделей через `CartTree` и интерфейсы `IModel`, `IRegressor`, `IClassifier`. Отдельная копия алгоритма дерева для леса не создаётся.

Поиск расширяется целочисленными кратностями, обычное обучение соответствует единичным кратностям. По условию у `SplitFinder::find_best` появляется последний необязательный `counts`: пустой span означает единицы, непустой имеет длину `X.rows()` и индексируется исходной строкой. Старое объявление заменяется расширенным, без второй неоднозначной перегрузки; прежние вызовы `DecisionStump` сохраняются. Условие также задаёт поиск на одном признаке `find_for_feature` с отдельным признаком константности и необязательным лучшим разбиением. Само выделение и реализацию выполняет студентка.

У служебного обучения дерева с кратностями длина массива равна числу исходных строк, нули допустимы, хотя бы одна кратность положительна. Общий `IModel::fit` не меняется ради произвольных весов. Предложенные в условии примеры организации параметров и расширения CART не дают агенту права проектировать API вместо студентки.

Нужно поддержать отсутствие ограничения глубины. Нулевое улучшение не запрещает допустимое разбиение при положительной неоднородности; отдельный положительный `min_impurity_decrease` не требуется. Сохраняются маршрутизация по `<=`, согласованность порога с критерием, неделимость одинаковых значений признака и детерминированные ничьи. Обычный CART с единичными кратностями и `All` сохраняет поведение №3 и совместимость с пнём.

**Различие контрактов глубины:** сейчас в №3 `max_depth=0` означает один лист, тогда как №4 задаёт необязательный положительный предел. Нельзя молча переопределить ноль или выбрать новый API вместо студентки. Способ расширения обсуждается с ней; старый контракт и тесты сохраняются.

### Bootstrap и взвешивание

При bootstrap выполняются равновероятные извлечения исходных индексов с возвращением. Повторения хранятся целочисленными кратностями, каждый исходный индекс узла присутствует не более одного раза; в корень входят индексы с положительной кратностью.

`min_samples_split` и `min_samples_leaf` проверяются по числу различных исходных индексов, а не по сумме кратностей. Разные строки с одинаковыми значениями признаков остаются разными объектами. Критерии разбиения, средние и частоты классов используют сумму кратностей и взвешенные агрегаты. Физическое размножение строк с подсчётом ограничений по копиям не заменяет эту семантику.

Отсутствие класса в bootstrap допустимо: нельзя добавлять его вручную или повторять извлечение до появления всех классов. При `bootstrap=false` все кратности единичные, а заданный `max_samples` является ошибкой.

### Случайные признаки

Политика просмотра признаков применяется заново в каждом узле. Фиксированный набор столбцов на всё дерево не подходит. Поддерживаются `All`, `Sqrt` и явное целое число; критерий и порог не становятся случайными. Среди рассмотренных признаков выбирается лучший допустимый порог.

Признаки просматриваются в случайном порядке без повторов. Обычно рассматриваются первые `q`. Если все первые `q` константны, просмотр продолжается до первого неконстантного или исчерпания признаков. Поэтому `q` не является безусловным пределом просмотра. Если неконстантный признак уже рассмотрен, отсутствие допустимого по размерам порога не требует расширять поиск любой ценой; при отсутствии допустимого результата получается лист. Кеширование константности от родителя не требуется.

### Агрегация и воспроизводимость

Регрессия усредняет предсказания деревьев. Классификация усредняет вероятности, а не числовые метки и не голоса по готовым меткам. Глобальные классы определяются по всему `y_train`; отсутствующему в дереве классу соответствует нулевая вероятность. Столбцы `predict_proba` согласованы с `classes()`, при ничьей выбирается меньшая исходная метка. Форма ответа и классы не меняются от запроса к запросу.

Каждое дерево получает уникальный seed, отличный от seed остальных деревьев. Общий `random_state` воспроизводимо формирует seed элементов в фиксированном порядке; один и тот же seed нельзя передать всем деревьям. У элементов собственные `std::mt19937`. При повторном `fit` генерация начинается заново.

Одинаковые данные, параметры и seed воспроизводят планы и ответы в одном окружении независимо от `n_jobs`. Другой seed не обязан менять каждый ответ. Совпадение RNG и результатов между C++ и sklearn или разными стандартными библиотеками не требуется. Проектирование этой схемы — самостоятельная часть.

### Обязательные параметры

Здесь `n` — число обучающих строк, `d` — число признаков. Таблица фиксирует условие и не задаёт структуры параметров, сигнатуры классов или хранение ансамбля.

| Параметр | Ограничение и явно заданное значение по умолчанию |
|---|---|
| `n_estimators` | Целое ≥ 1; по умолчанию 100 |
| `bootstrap` | По умолчанию `true`; `false` использует все исходные строки |
| `max_samples` | Необязательное целое `m` от 1 до `n`; отсутствие означает `m=n`; заданное значение при `bootstrap=false` — ошибка |
| `max_features` | `All`, `Sqrt` или целое от 1 до `d`; классификация по умолчанию `Sqrt`, регрессия `All` |
| `max_depth` | Необязательный положительный предел; отсутствие означает рост до других условий остановки |
| `min_samples_split` | Целое ≥ 2; по умолчанию 2 |
| `min_samples_leaf` | Целое ≥ 1; по умолчанию 1 |
| `random_state` | Явный целочисленный seed; значение по умолчанию для леса в таблице условия не задано |
| `n_jobs` | Целое ≥ 1; значение по умолчанию в условии не задано |

Для `Sqrt`: `q=max(1, floor(sqrt(d)))`; для `All`: `q=d`. Дробные варианты и `log2` не требуются. Критерии фиксированы: Gini для классификации и squared error для регрессии.

## Совместимость и качество

- C++20, отдельные библиотека ядра, приложения и тесты CTest; сборка без предупреждений при `-Wall -Wextra`.
- Сохраняются интерфейсы моделей, прежние реализации и тесты №1–3; необходимые расширения CART не запрещены, но алгоритмы пишет студентка.
- RowMajor и ColumnMajor дают логически одинаковые ответы с разумными вещественными допусками.
- Ядро сообщает ошибки исключениями и не печатает; приложение перехватывает их по ссылке, выводит сообщение и возвращает ненулевой код.
- Проверяются размеры, пустое обучение, отсутствие признаков, параметры, конечность данных, обученность и число признаков запросов. Ноль тестовых строк возвращает результат правильной формы, включая `0 × C` для вероятностей.
- После `fit` нет висячих ссылок, `span` и `MatrixSlice` на локальные данные. Конструктор не обучает; повторный `fit` перестраивает модель, не накапливает деревья. `predict` и `predict_proba` не изменяют обученное состояние.
- При ошибке обучения частичный ансамбль не считается обученным. Условие допускает сохранение прежнего состояния или явный сброс, но текущий CART №3 при ошибочном `fit` сбрасывает обучение. Агент не меняет этот контракт без обсуждения со студенткой; выбранное поведение документируется и проверяется.
- Debug использует ASan/UBSan. ThreadSanitizer при необходимости и поддержке средой запускается отдельно, одновременно с ASan не подключается.
- Сторонние реализации ML-алгоритмов и метрик не используются в рабочем C++-коде.

Будущее приложение сравнивает обычный CART и лес на одной обучающей части, показывает параметры, несколько ответов и вероятностей, размеры деревьев и времена. Для диагностики достаточно MAE или accuracy в приложении, без отдельной системы метрик и подбора параметров. Документация описывает фактические владение и создание моделей, random_state, порядок суммирования, обработку ошибок потоков и стоимость вычислений. Агент не описывает отсутствующие компоненты как готовые.

## Тестирование и измерения

Существующие тесты №1–3 должны сохраняться и проходить после расширения проекта. Новые сценарии должны покрывать:

- один элемент без bootstrap с `All` против обычного CART с теми же ограничениями при однозначных разбиениях;
- усреднение вероятностей вместо голосования: в частности, два дерева с вероятностью A `0.51` и третье с `0` дают среднюю вероятность A `0.34` и позволяют различить эти способы для двух классов;

- одинаковый seed, повторный `fit`, разные `n_jobs`, оба layout;
- один объект, один признак, константную матрицу, пустой пакет запросов, неверные параметры и исключение рабочей задачи.

Для точных ожидаемых ответов использовать контролируемые входы, кратности и планы; не рассчитывать на случайно удачную выборку. Свойства RNG проверять отдельно. Независимый медленный подсчёт остаётся тестовым эталоном и не переносится в ядро. Вспомогательные тестовые типы не должны усложнять рабочий API. Предметный смысл и ожидаемые результаты проверяет студентка.

В необязательной сверке со sklearn 1.8.0 использовать для точного сравнения одно дерево, `bootstrap=False`, все признаки, одинаковые ограничения, простые представимые числа и единственный лучший порог. Сравнивать ответы и вероятности, не внутреннюю нумерацию узлов. Проверку весов можно сверить с `DecisionTreeRegressor/Classifier.fit(..., sample_weight=counts)` на данных, различающих уникальные индексы и сумму кратностей. Для случайного леса одинаковый числовой seed Python/C++ не задаёт одинаковые извлечения; ручные проверки используют одинаковые заранее подготовленные кратности.

Сборку и проверки кода выполнять в WSL, в отдельном `build-codex`, по командам `AGENTS.md`; существующий `build` не трогать. При недоступности WSL запросить необходимый запуск по правилам окружения. Не устанавливать зависимости без согласия. Не считать тесты пройденными без запуска; успех санитайзеров относится только к выполненным сценариям.

Измерения — Release без санитайзеров, одинаковые данные и параметры. Отдельно измеряются подготовка данных, `fit` и пакетный `predict`; чтение CSV не включается в предсказание. Сравниваются `n_jobs=1` и хотя бы одно большее значение; сообщаются медиана нескольких запусков, размеры, параметры, число потоков, компьютер и компилятор. Ускорение — `T1/Tp`; отсутствие ускорения объясняется, а не скрывается. Нельзя выдумывать замеры или требовать улучшения точности и линейного ускорения для зачёта.
