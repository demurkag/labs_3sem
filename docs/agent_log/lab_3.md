### Ошибка первоначального эталона и её исправление

При первом запуске упала `split_finder_reference`; остальные 12 функций
новой программы выполнились успешно. В CTest прошли 2 из 3 целей.

Вход проблемного сравнения:

- Variance, `min_samples_leaf = 1`, разрешённые признаки `{2, 0}`;
- выбранные строки `{5, 1, 3, 0}`, отклики в этом порядке `{-1,-1,-2,-2}`;
- значения признака 0: `{0,-1,-1,2}`;
- значения признака 2: `{2,0,1,-1}`.

Эталон ожидал признак 0 с порогом 1, реализация вернула признак 2
с порогом 1.5. Математически обе оценки равны `28/3`.
Но первоначальный эталон ранжировал их в `long double` с допуском,
а контракт пня разрешает ничью только при строго одинаковых
вычисленных `double`-оценках. Допуск объединял различающиеся
результаты округления.

Это была ошибка предложенного агентом тестового эталона.
Агент исправил его на независимый полный пересчёт групп в `double`
со строгим сравнением при выборе победителя. Допуски остались
для сравнения численных результатов. Проверки признака, маршрутизации
и специально подготовленных точных ничьих не удалялись.
Исходники моделей для прохождения теста не менялись.
