## Ограниченная многопоточность случайного леса

### Запрос и согласованные решения

Студентка сообщила о готовности последовательных RandomForestRegressor и
RandomForestClassifier и прохождении четырёх целей CTest. Она поручила агенту
внести многопоточность и задала её организацию: предварительная
генерация индивидуальных seed в прежнем порядке, создание всех деревьев до
запуска задач, локальные RNG и counts, статическое распределение индексов
`w, w+p, w+2*p`, `p=min(n_jobs,n_estimators)`, последовательный путь при `p=1`,
отдельные результаты деревьев и агрегация после ожидания в порядке их номеров.
Запрос явно разрешает создание этого журнала.

### Вклад агента

- Прочитаны правила №4, условие `C:/Users/krist/Downloads/lab_4_star.md` и
  актуальный код. Предварительные решения по параллелизму взяты из запроса
  студентки; алгоритмы CART, SplitFinder, bootstrap и генерации seed не менялись.
- Добавлен внутренний `src/forest_tasks.hpp`: `std::jthread`, захват `w` по
  значению, явный `join()`, отдельный `exception_ptr` на задачу, `current_exception`
  и `rethrow_exception`. После ошибки рабочий продолжает оставшиеся задачи;
  после завершения всех потоков передаётся первая ошибка по индексу дерева.
  Если создание потока бросает исключение, уже запущенные потоки завершаются
  через RAII до уничтожения захваченных объектов.
- В обоих лесах создание деревьев отделено от обучения. `trees_` очищается
  в начале fit и получает новый ансамбль только после успешного завершения задач.
- Распараллелены predict регрессора и predict_proba классификатора. Формулы,
  порядок суммирования, classes и predict классификатора сохранены.
  Временное хранение результатов требует O(B*N) double для регрессии и
  O(B*N*C) для классификации, где N — размер пакета, C — число классов.
- В CMake добавлены `find_package(Threads REQUIRED)` и публичная зависимость
  core от `Threads::Threads`.
- Существующие тесты сохранены; добавлены две группы: точное совпадение ответов
  для n_jobs=1,2,3,12 при одном и семи деревьях, bootstrap с обоими значениями,
  оба layout, повторный fit после замены данных, одинаковый seed, пустые запросы;
  статическое распределение задач, последовательное выполнение без нового
  потока, завершение всех задач перед передачей ошибки, сохранение типа и выбор
  ошибки по индексу. Проверены ошибки предсказания обоих лесов, численная ошибка
  внутри обучения регрессора, сброс обученности и последующее восстановление.
